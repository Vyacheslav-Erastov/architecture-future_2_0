# Стратегический роадмап

Роадмап разбит на три этапа, соответствующие описанным в задании (0-6 мес, 6-18 мес, 18-36 мес). Указаны ключевые роли и их вовлечённость.


## Этап 1: Пилот (0-6 месяцев)

### Цель
Проверить концепцию Data Mesh на одном-двух доменах, создать базовую платформу.

| Задачи                                                                                               | Роли                                     | Результат                                                   |
| ---------------------------------------------------------------------------------------------------- | ---------------------------------------- | ----------------------------------------------------------- |
| Создание платформенной команды (Data Platform Team)                                                  | Platform Lead, Data Engineer, DevOps     | Инфраструктура как код (Terraform) развёрнута в облаке.     |
| Выбор пилотного домена (например, «Пациентский поток» или «Финансовые расчёты»)                      | Domain Data Product Owner, Data Engineer | Определён первый дата-продукт.                              |
| Развёртывание событийной платформы (Kafka) и Data Lakehouse (S3+Iceberg)                             | Data Engineer, DevOps                    | Kafka-кластер, Schema Registry, подключение к S3.           |
| Реализация первого дата-продукта: публикация событий из операционной системы, загрузка в Iceberg     | Data Engineer (домена), Domain Expert    | События публикуются, доступны для аналитики.                |
| Создание портала самообслуживания (MVP) с каталогом данных (DataHub) и базовым конструктором отчётов | Frontend/Backend разработчики            | Пользователи пилотного домена могут строить простые отчёты. |
| Обучение команды пилотного домена                                                                    | Тренеры, Platform Team                   | Команда готова к самостоятельной работе.                    |
| Бизнес-цель: Ускорение отчётности по выбранному домену в 2 раза.                                     |                                          |

## Этап 2: Масштабирование (6-18 месяцев)

### Цель
Расширение Data Mesh на критические домены, внедрение федеративного управления и потоковой аналитики.

| Задачи                                                                                                 | Роли                                                           | Результат                                                                     |
| ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Подключение новых доменов (Медицинские записи, ИИ-сервисы, Инвентаризация)                             | Data Product Owners новых доменов, Data Engineers              | Каждый домен публикует свои дата-продукты.                                    |
| Внедрение федеративного управления: общие стандарты схем, качества данных, политик безопасности        | Data Governance Council (представители доменов), Data Stewards | Разработаны и приняты Data Contracts.                                         |
| Реализация потоковых витрин (Kafka Streams / Flink) для near-real-time аналитики                       | Data Engineers (платформа), Streaming Engineers                | Появляются витрины с задержкой < 1 минуты.                                    |
| Создание антикоррупционных слоёв для интеграции с легаси (Camel, DWH)                                  | Integration Engineers                                          | Легаси-системы подключаются через ACL, события публикуются в Kafka.           |
| Расширение портала: конструктор сложных отчётов, поддержка подписок на события                         | Frontend/Backend разработчики                                  | Пользователи могут создавать кастомные отчёты и подписываться на уведомления. |
| Запуск программы обучения для новых доменных команд                                                    | Platform Team, Тренеры                                         | Повышение компетенций внутри компании.                                        |
| Бизнес-цель: Охват 80% ключевых бизнес-процессов, сокращение времени на получение отчётности в 3 раза. |                                                                |


## Этап 3: Полноценная платформа и инновации (18-36 месяцев)

### Цель

Полный отказ от легаси, переход к слабосвязанной событийной платформе, поддержка новых бизнес-направлений.

| Задачи                                                                                                           | Роли                                | Результат                                                  |
| ---------------------------------------------------------------------------------------------------------------- | ----------------------------------- | ---------------------------------------------------------- |
| Вывод из эксплуатации легаси DWH и шины Camel                                                                    | Архитекторы, Integration Engineers  | Все данные доступны через дата-продукты.                   |
| Поддержка самообслуживания для внешних партнёров (фарма, производители) через API                                | Data Product Owners, API Developers | Партнёры могут подключаться к данным через защищённые API. |
| Внедрение Data Observability (автоматический мониторинг качества, lineage)                                       | Platform Team, Data Stewards        | Проактивное выявление проблем с данными.                   |
| Развитие ML-платформы: Data Scientists могут самостоятельно получать данные для моделей                          | ML Engineers, Data Scientists       | Модели обучаются на актуальных данных из Data Lakehouse.   |
| Интеграция новых географических регионов с учётом локальных требований                                           | Domain Teams, Compliance            | Локальные инстансы платформы, соблюдение регуляций.        |
| Оптимизация затрат на облако (автомасштабирование, Spot-инстансы)                                                | DevOps, FinOps                      | Снижение TCO без потери производительности.                |
| Бизнес-цель: Поддержка трёх новых регионов, запуск 5 новых продуктов в год, time-to-market для отчётов - минуты. |                                     |

## Ключевые роли в роадмапе

Data Product Owner - представитель бизнеса, отвечающий за дата-продукт: требования, качество, развитие.

Data Engineer (доменный) - разрабатывает и поддерживает пайплайны данных внутри домена, публикует события.

BI-аналитик - работает с порталом, строит отчёты, формулирует требования к дата-продуктам.

Platform Data Engineer - развивает платформу (Kafka, Iceberg, DataHub, Trino), обеспечивает стабильность и самообслуживание.

Data Governance Lead - координирует федеративное управление, стандарты.

DevOps - автоматизация инфраструктуры, CI/CD, мониторинг.

Тренеры/Change Managers - обучение и поддержка команд при переходе.
